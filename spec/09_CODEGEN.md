# BoneScript Code Generation Specification

## 1. Purpose

Code generation (codegen) is the final compilation stage. It transforms the
verified, optimized IR into executable target code.

Codegen is NOT creative. It is a **deterministic mapping** from IR nodes to
code templates. Every IR construct has exactly one code representation per target.

## 2. Target Languages

| Target | Used For | File Extension |
|--------|---------|---------------|
| TypeScript | API services, business logic, frontend | `.ts` |
| Go | High-performance workers, infrastructure services | `.go` |
| SQL | Database schemas, migrations | `.sql` |
| YAML | Infrastructure configuration, deployment | `.yaml` |
| JSON | API schemas, package manifests | `.json` |

## 3. Codegen Rules

### Rule 1: Total Coverage
Every IR node MUST produce code. No IR node may be silently dropped.
If a node cannot be mapped, codegen fails with an error.

### Rule 2: No Orphan Code
Every line of generated code must trace back to an IR node.
No "helper" code that doesn't correspond to the IR.

### Rule 3: No Hidden Behavior
Generated code must not do anything not specified in the IR.
No implicit logging, no implicit retries, no implicit caching
unless declared in the IR.

### Rule 4: Deterministic Formatting
Code is formatted according to fixed rules (not a configurable prettifier):
- Indentation: 2 spaces
- Line length: max 100 characters (break at logical points)
- Braces: same line (K&R style)
- Imports: sorted lexicographically, grouped by source

### Rule 5: Self-Contained
Generated code must compile/run without manual intervention.
All imports must resolve. All types must be defined. All dependencies declared.

## 4. Template System

Codegen uses **structural templates** â€” not string interpolation.
A template is a function: `IRNode â†’ AST of target language â†’ formatted code`.

### 4.1 Template Structure

```
Template = {
  match:    IRNodePattern,        -- what IR nodes this template handles
  requires: List<Import>,         -- what imports the generated code needs
  emit:     IRNode â†’ TargetAST    -- the generation function
}
```

### 4.2 Template Registry

Templates are registered in a fixed order. For each IR node, the FIRST
matching template is used. This eliminates ambiguity.

### 5.3 StateMachine â†’ Transition Function

```
StateMachineIR { entity: "Item", states: [...], transitions: [...] }
```
Generates:
```typescript
export type ItemState = "available" | "reserved" | "consumed" | "deleted";

export const ITEM_TRANSITIONS: Record<ItemState, Partial<Record<string, ItemState>>> = {
  available: { reserve: "reserved", delete: "deleted" },
  reserved: { release: "available", consume: "consumed" },
  consumed: {},
  deleted: {},
};

export function transitionItem(
  current: ItemState,
  trigger: string,
  guard?: () => boolean
): Result<ItemState, TransitionError> {
  const next = ITEM_TRANSITIONS[current]?.[trigger];
  if (!next) {
    return err(new TransitionError(current, trigger));
  }
  if (guard && !guard()) {
    return err(new GuardFailedError(current, trigger));
  }
  return ok(next);
}
```

### 5.4 Event â†’ Type + Publisher

```
EventIR { name: "PlayerCreated", payload: [...] }
```

```typescript
export function emitPlayerCreated(
  payload: PlayerCreatedEvent["payload"],

  return bus.publish({
    type: "PlayerCreated",
    payload,
    metadata: {
      source: "PlayerService",
      correlationId: context.correlationId,
      causationId: context.causationId,
    },
  });
}
```

## 6. SQL Codegen Rules

### 6.1 Model â†’ CREATE TABLE

```
ModelIR { name: "Player", fields: [...], indexes: [...] }
```
Generates:
```sql
-- Generated by BoneScript compiler. DO NOT EDIT.
-- Source hash: {hash}

CREATE TABLE IF NOT EXISTS players (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  username VARCHAR NOT NULL,
  score BIGINT NOT NULL DEFAULT 0,
  CONSTRAINT players_username_unique UNIQUE (username)
);

CREATE INDEX IF NOT EXISTS idx_players_created_at ON players (created_at);
CREATE INDEX IF NOT EXISTS idx_players_username ON players (username);

-- Trigger for updated_at
CREATE OR REPLACE FUNCTION update_players_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_players_updated_at
  BEFORE UPDATE ON players
  FOR EACH ROW
  EXECUTE FUNCTION update_players_updated_at();
```

### 6.2 Type Mapping (BoneScript â†’ SQL)

| BoneScript Type | PostgreSQL Type |
|------------|----------------|
| string | VARCHAR |
| uint | BIGINT CHECK (value >= 0) |
| int | BIGINT |
| float | DOUBLE PRECISION |
| bool | BOOLEAN |
| timestamp | TIMESTAMPTZ |
| uuid | UUID |
| bytes | BYTEA |
| json | JSONB |
| list<T> | JSONB |
| set<T> | JSONB |
| map<K,V> | JSONB |
| optional<T> | T (nullable) |

## 9. Codegen Verification

After generation, the compiler verifies:
1. All generated TypeScript files parse without syntax errors
2. All SQL files parse without syntax errors
3. All YAML files are valid YAML
4. All JSON files are valid JSON
5. All imports resolve to generated files
6. No circular imports exist
7. Every IR node has at least one corresponding output line (traceability)
